# El item set 5 — signage & platform details (rework)

Scope: `el_name_board`, `el_exit_sign`, `el_platform_edge`, `el_wood_platform`.
All assets regenerated by `python3 tools/gen_el_assets.py` (green, `verify()`
passes). Offline renders in `el_set5_renders/` (geometry renders are flat-shaded
and painter-sorted — a small bracket bleeding through a large plate in those
images is a sorting artifact of the toy renderer, not the model). NOT compiled
(no Gradle allowed in this worktree) and NOT in-game tested.

## 1. Name board — three mounts (the big one)

`el_name_board` used to be legs-only: placed anywhere but on a windscreen top it
floated. It now carries `MOUNT = standing | wall | hanging`, picked from the
clicked face exactly like `ElExitSignBlock`:

| clicked face | MOUNT | FACING | reads |
|---|---|---|---|
| side of a block (horizontal) | `wall` | the clicked side | out of the wall |
| top of a block / floor / windscreen rail | `standing` | player look **reversed** | away from the placer |
| underside of a block (ceiling) | `hanging` | player look **reversed** | away from the placer |

`standing`/`hanging` keep the facing-decor convention every other decor block in
this mod uses (`getHorizontalPlayerFacing().getOpposite()`); the board is
double-sided so either face reads. `wall` takes the clicked side so the plate
faces out of the wall, matching the exit sign.

Models: `el_name_board_model` (standing, geometry byte-identical to before —
only JSON key order moved), `el_name_board_hanging`, `el_name_board_wall`.
Blockstate is now `variants` on facing x mount (12 states, was 4 multipart
parts). Old placements default to `mount=standing` and render exactly as before.

### Plate-plane math (the careful part)

The letters are painted by `StationDecorRenderer.paintElNameBoard`, not by the
model, so the plate plane is a three-way contract:
`NAME_BOARD_PLATE` in `tools/gen_el_assets.py` -> the model -> the renderer
(and the same table is repeated in the `ElNameBoardBlock` javadoc).

```
mount     plate box (model px)          top   front  faces drawn
standing  x 1..15  y 6..13  z 7.4..8.6   13    7.4    both
hanging   x 1..15  y 5..12  z 7.4..8.6   12    7.4    both
wall      x 1..15  y 5..12  z 13.8..15   12   13.8    front only
```

Every plate is **14 x 7 px**, deliberately: the renderer's canvas stays 56 x 28
units (64 units/block) and the text fitting (`size = min(11, 50/width)`,
centred at 28, 14 - size/2) is untouched. Only two numbers move.

Renderer derivation — after the caller's `translate(0.5, 0, 0.5)` +
`rotate(180 - facing)` the viewer is on local -Z and model coordinate `m` maps
to local `m/16 - 0.5`, so the canvas origin is

```
translate(x=15 -> 0.4375,  y = top/16,  z = front/16 - 0.5 - 0.008)
scale(-UNIT, -UNIT, UNIT)            // canvas x grows toward model x=1, y down
```

which reproduces the old hard-coded `(0.4375, 0.8125, -0.0375 - 0.008)` exactly
for the standing board (13/16 = 0.8125, 7.4/16 - 0.5 = -0.0375). The back face
reuses the *same* translate because a 180 deg Y rotation negates local x and z
and the standing/hanging plates are centred on z = 8 — the identical numbers
land on the far face. The wall plate is **not** centred (it is up against the
wall), which is exactly why it is drawn one-sided; drawing side 1 there would
paint the letters inside the wall.

Outline shapes moved into `ElNameBoardBlock` (per-mount, rotated with
`FacingDecorBlock.rotations`) so `MtrStationDecor` did not have to change.

## 2. EXIT sign

- **Sheet rebuilt at 64 px** (was 32), four 16-row zones. Zone tops stay at uv
  v = 0/4/8/12, so the model's zone contract is unchanged; each sign face now
  takes the *whole* zone, `uv [0, v0, 16, v0+4]`.
- **Legibility**: "EXIT" is drawn at `scale=2` (10 px glyphs, was 5) and the
  arrows are real 3 px shafts with 11 px chevron heads (`_tri_down`,
  `_tri_side`). The old down arrow was a 2 px bar with four stray pixels for a
  head and did not read at all — see `tex_exit_sheet.png` and
  `tex_exit_plates.png` (the latter squeezes each zone to the plate's real
  aspect before blowing it up, i.e. what the block actually shows).
- **Proportions**: plate is now **12 x 3.5 x 0.8 px** (was 12 x 7 x 1.0) — 0.75 m
  x 0.22 m, the wide thin strip the real signs are. It is 3.43:1 against the
  zone's 64:16 = 4:1, a 14 % vertical squeeze that is invisible on the
  lettering. Going to the 0.5 m in the brief would mean an 8 x 2 px plate at
  this aspect, which is neither readable nor clickable, so 0.75 m is the
  chosen compromise.
- **Wall mount** now sits on a visible standoff: plate at z 14.2..15.0 (1 px off
  the wall) on two brackets z 14.6..16 whose front ends are *buried inside* the
  plate (no coplanar faces) and whose face against the wall is omitted. The
  plate also gained a back face — previously the wall model had no south face
  at all, so it was see-through at grazing angles.
- Java outlines updated to match (hanging 2,8,7.2 -> 14,16,8.8 so the stub is
  clickable; wall 2,7.5,14 -> 14,12,16).
- **Found, not fixed (not my files):** `el_lamp_gooseneck` / `el_lamp_post_head`
  paint their bulb "glow" with `#exit` at uv (13..15, 4.4..5.4), which lands on
  a *black* patch of this sheet — the lamps have black bulbs today. I kept the
  right ~12 columns of every zone free of artwork so the behaviour is unchanged
  rather than made worse; the real fix is a tiny glow texture (or a lamp-owned
  sprite) for those two models.

## 3. Platform edge

- **Texture -> 32 px** (`tex_concrete_edge`). The tactile strip is now three
  staggered rows of **truncated domes** on a 4 px pitch (8 per block, which
  divides 32 so the grid runs unbroken along a platform): each dome is a 2x2
  cell of lit yellow with a shaded bottom-right corner, over the yellow field,
  with a concrete groove behind. The old version was a solid yellow band with
  alternating dark *columns*, which read as a barcode. Concrete below stays
  per-column-only (the same sprite skins the vertical faces).
- **Overhang lip added**: the slab's nosing, `y 12.6..16, z -1..0`, i.e. 1 px
  (~6 cm, the real 2–3 inch overhang) proud of the fascia, with the concrete
  top continuing over it and a dark underside. Its **south face is omitted** —
  it would be exactly coplanar with the cube's own north face.
- **Fascia coordinated with `el_girder`**: two shallow flanges (`y 1.2..3.0`
  and `9.2..11.0`, 0.8 px proud, south faces omitted for the same reason)
  sampling the girder's flange band, with the web slice on their up/down faces.
  The block stays a full opaque cube — only the track side, which is always open
  air, carries relief, so nothing breaks vanilla culling.
- Renders: `platform_edge_row.png` (three in a row + wood platform behind),
  `platform_edge_one.png`, `tex_platform_edge_strip.png`.

## 4. Orientation audit

`el_platform_edge` is a plain `FacingDecorBlock`, so `getPlacementState` gives
`FACING = playerFacing.getOpposite()`. The model authors the tactile strip and
the fascia on the **north = FACING** side, so the rule is:

> **Stand on the platform, face the track, place** — the yellow dome strip, the
> fascia and the overhang lip land on the track side (away from you).

That is the same convention as every other facing-decor block here (bench, zebra
board, railing), so it needed no Java change; it is now written down in the
generator docstring. The alternative ("strip on the side you clicked") was
rejected: it would make the block behave unlike its whole family, and placing a
floor block by clicking its own side is the unusual case.

Sign mounts (both `ElNameBoardBlock` and `ElExitSignBlock`, now documented in
both javadocs): **clicked wall -> plate on that wall facing out of it; clicked
floor/ceiling -> the placer's look direction reversed**, i.e. the sign reads
toward where you were standing when you placed it from the other side and away
from you on the near side — consistent with the rest of the decor family.

## 5. Proposals (deliberately NOT built)

1. **`el_wood_platform` plank AXIS.** The planks are per-column in the texture,
   so on the top face (u=x, v=z) they run north–south always; real platform
   planking runs *across* the platform, so a rotated deck needs the boards
   turned. The cheap version is a `Properties.AXIS`-style horizontal axis
   property (x/z) taken from the placer's facing, with the blockstate applying
   `y: 90` to the same model — no new texture, no new block id. It needs the
   block in `MtrStationDecor` to stop being a plain `net.minecraft.block.Block`
   (a two-line `PoleBlock`-style class, as `stop_marker_pole` already does), so
   it is a registration change and out of this set's file scope. Old placements
   default to `axis=z` and look exactly like today.
2. **Two-block-wide merging name board.** The photos' Bay Parkway board is
   ~2.5 m x 0.4 m, i.e. about 2.5 blocks; ours is one block (14 x 7 px). The
   merging machinery already exists twice in this repo (`RailingSignBlock` runs
   and `DepartureBoardBlock.rectangle`): give `ElNameBoardBlock` LEFT/RIGHT
   booleans computed from same-block+same-facing+same-mount neighbours, let the
   run's min-coordinate segment draw one canvas across the run (others return
   early), and drop the plate's end faces on joined sides so a run reads as one
   panel. That is a renderer + block change of real size, hence a proposal.
3. **Wider tactile strip.** The dome band is uv rows 0..5 (~31 cm). Real
   warning strips are ~60 cm. Widening means moving the side faces' uv window
   (rows 6..16) in step — trivial, but it changes how much yellow a platform
   shows, so it is a taste call for Thomas.
